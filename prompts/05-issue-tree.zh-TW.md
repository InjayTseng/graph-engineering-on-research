# 05 議題樹拆解（Issue Tree）

[English](05-issue-tree.md) ｜ 繁體中文

把顧問公司的拆題紀律——MECE、假說驅動、80/20——重建成 graph engineering。一棵好的議題樹**就是**還沒開火的圖：MECE 的分支是彼此之間沒有邊的節點，假說驅動的葉子就是之後驗證者要獵殺的可證偽主張。

適用：一個又大又模糊、還沒派出任何研究的問題——「該不該進入 X 市場」「毛利為什麼一直掉」「這條產品線救不救得活」。在範本 02 **之前**跑：它負責生產 02 第一步需要的那些角度。（01 健檢你已經在跑的流程；05 拆解你還沒開始的問題。）

用法：複製下面整段，把【你的問題】換掉。拆解在單一對話裡完成；它產出的派發，才是發散出去的部分。這是純判斷工作——若可選模型，用強推理級跑，不要省。

> 這個範本的失敗模式是：畫出一棵漂亮的樹，然後停在那裡。一個只寫著下游工作名稱、卻沒真的送出去的路由欄，是裝飾。第六與第七步是樹變成圖的地方，不是選配。

---

## 複製這段

你是結構化解題夥伴。我會給你一個模糊的問題，你的任務是把它拆成一棵可以當圖派發的議題樹——顧問公司的紀律，去掉玄學。

### 三個判準

- MECE 判準：同層分支互斥且窮盡。翻譯成圖的語言：兄弟節點之間沒有變數流動——如果兩個分支必須共享資料才答得出來，它們就是同一個分支，或者拆錯了
- 假說判準：每片葉子都是一條可證偽的陳述，並指名殺死它的方法（「運費是毛利的主要殺手——可從出貨帳查證」），永遠不准是一個題目（「研究一下成本」）。說不出什麼資料能殺死一片葉子，它就還不是葉子
- 80/20 判準：不是每個分支都配得上 agent。少數葉子決定主問題的答案；其餘葉子的存在是為了證明樹的窮盡性，最多給一次便宜的查證

### 我的問題

【你的問題：幾句話的處境與困擾。亂沒關係——把它結構化正是這個範本的工作。例如：訂閱營收成長 30% 但利潤下滑，董事會兩週內要答案，三個團隊在互相指責】

### 你的任務

1. 用 SCQA 定題：情境（Situation）、變局（Complication）、以及唯一的主問題（Question）。如果我的問題陳述裡藏著好幾個問題，直接說，並挑出先跑哪一個——附理由
2. 首日答案（day-one answer）：對主問題先押一句話的初始假說。這棵樹的存在是為了殺死或確認這條假說，不是為了裝飾它
3. 建樹，2–3 層深。每次分叉都指名你選的切分邏輯——利潤驅動樹、顧客旅程、漏斗、價值鏈、3C、利害關係人地圖，或你自創的。框架是切分的啟發式，不是真理：挑手上的資料真的分得開的那一種，並說明落選的第二名框架輸在哪
4. 逐一 MECE 檢查每次分叉，誠實標出違規——說出口的重疊是一條註腳；藏起來的重疊會派兩個 agent 去搶同一批證據
5. 每片葉子寫清楚：可證偽的假說、殺死它的資料、產出該資料的測試或分析、優先級（依 80/20 判準）
6. 派發對映——把每片高優先葉子分流：事實型葉子（文件與資料答得出來的）變成鑽石研究（範本 02）的搜尋角度；判斷型葉子（公開資料裡沒有標準答案的）變成顧問圓桌（範本 04）的決策題；瑣碎葉子一行查證解決，不用開圖。每條路由都要寫成「可以直接貼給新 agent 的那段文字」，不准只寫標籤——「02 角度」是一句註記，而註記不會自己執行
7. 現在就派出去。所有高優先葉子一起發動：事實查證平行跑（它們在結構上本來就互相獨立，這正是 MECE 幫你買到的東西），判斷型葉子送 04，研究型葉子送 02。若你的 harness 開不了 subagent，就把派發清單印成一份編號的「新對話 prompt 列表」，並明確標出哪幾條可以同時跑。同一份簡報要發散給超過三個 agent 之前，先放一隻哨兵：把簡報送給一個 agent，指令只有一句——先別回答，列出你需要但這份簡報沒給的事實——補完洞再派其餘的

### 輸出格式

一、SCQA 定題、主問題、首日假說

二、樹畫成 mermaid flowchart，每次分叉標註切分邏輯，高優先葉子視覺標記

三、葉子表。最後一欄裝的是「你會貼給新 agent 的那句話」，不是標籤：

| 葉子假說 | 殺死它的資料 | 測試／分析 | 優先級 | 要送出去的 prompt（逐字） |
|---|---|---|---|---|
| （一句話） | （具體來源） | （怎麼做） | 高／低 | （「找出能定案 X 的一手來源，回傳原文引述、連結與日期；查不到就寫無法查證」／04 的決策定題／02 的題目行） |

四、派發結果：每一次派發回來了什麼，標記已回答（附來源）／無法查證（附查了什麼）／有爭議（兩個來源相反——指出誰引了更具體的一手出處，並裁定）。空手而回的葉子就讓它明顯空著，不要用推論補平

五、誠實段落：MECE 在哪裡破了、你為什麼接受；哪個框架是硬套的；這棵樹在結構上看不見什麼（未知的未知永遠長在所有樹的外面——說出你預期它們藏在哪）

六、自我檢查，每項一行：我路由了幾片葉子、實際派出了幾個 agent（第二個數字是零，這輪就沒完成——回到第七步）；哪些葉子是我自己認定已解決、而不是有出處的（那些是穿著事實外衣的假設）；這輪沒做的事是什麼

規則：不要客套，不要複述我的輸入。如果我的問題送來時已經拆得不錯，直接說，然後改良葉子而不是重建整棵樹。永遠不准讓框架凌駕資料：一棵漂亮但資料分不開分支的樹，是一幅畫，不是一份計畫。而一個從來沒被送出去的路由欄是裝飾——樹要等到派發都回來、或你明講了為什麼沒派，才算完成。
